Upload the angles that show the damage. Why these figures and not the higher ones

Mask, not box. Box mAP for this run is {{ ev.BOX_MAP50|floatformat:3 }} / {{ ev.BOX_MAP50_95|floatformat:3 }}, which is higher than the mask figures above. It is recorded in core/evaluation.py purely so nobody quotes it by accident: a bounding box has no usable area for this pipeline, since a diagonal scratch fills only about 15% of its box. Severity comes from the polygon, so mask mAP is the honest description of the system.

Test, not validation. The validation split scores {{ ev.VALID_MASK_MAP50|floatformat:3 }} / {{ ev.VALID_MASK_MAP50_95|floatformat:3 }}, and is not reportable: best.pt was selected by watching it, so it stopped being held out the moment it chose a checkpoint. The gap between the two splits is a useful generalisation check and nothing more. It is not leak evidence — leakage inflates test scores, so it would close the gap rather than open one. Split integrity is established instead by the assertions in tools/prepare_dataset.py, which refuse to report success unless all three leak conditions hold.

Precision {{ ev.MASK_PRECISION|floatformat:3 }}, recall {{ ev.MASK_RECALL|floatformat:3 }}. Recall below precision means the system misses damage more often than it invents it. For an estimate that is the safer direction to err, but it is still a miss: an assessment produced here is a first pass, not a final settlement.

Accuracy does not track training volume

Spearman ρ = {{ ev.VOLUME_CORRELATION|floatformat:2 }}

The correlation between how much training data a class has and how accurately it is detected is negative. The three most accurate classes are the three rarest in the training set, and the class with the most data of any is third worst.

  • Tyre flat — {{ ev.CLASS_RESULTS.6.train_instances }} training instances, the fewest, and the most accurate class at ≈{{ ev.CLASS_RESULTS.6.map50|floatformat:2 }}.
  • Scratch — {{ ev.CLASS_RESULTS.2.train_instances }} training instances, the most of any class, and third worst at {{ ev.CLASS_RESULTS.2.map50|floatformat:3 }}.

What predicts accuracy here is not data volume but whether the damage has an edge an annotator can agree on. A flat tyre and a shattered window have boundaries; a crack and a scratch are arguments. So a weak class on this system is never explained by "not enough data" — the measured correlation contradicts that explanation directly.

What this system does not do

Stated before it is asked
  • Cars only. The training data is CarDD, which contains no two-wheelers. Nothing here has been measured on a motorcycle or a scooter and none should be submitted to it.
  • External damage only. Detection works from photographs of the outside of the vehicle. Mechanical, structural and internal damage are outside the scope entirely.
  • No re-identification across views. When several photographs show damage, the combined estimate takes the maximum per part rather than the sum — a bumper photographed twice is still one bumper to buy. The system cannot tell one bumper's dent from another's, so max is the conservative reading: it can understate genuinely separate damage, but it cannot invent damage that is not there.
  • Not a quotation. Prices are ranges from a published repair price list ({{ cost_source }}), not from a garage, a parts supplier or an insurer. Labour rates, paint and regional variation are not modelled separately.

What this project changes

  • Severity is measured, not predicted. The training data carries no severity labels, so a severity classifier would have had nothing honest to learn from. The verdict shown on every result is the measurement beside the threshold that banded it.
  • Cost is itemised, not regressed. Each damage maps to a repair action and a price range from a published list, so a reader can see which line drives the total instead of receiving one number.
  • Repair, not replacement. The estimate prices repairing the damage. Only lamps and glass, which cannot be repaired, are priced as replacements, and the report labels them as such.
  • A part is bought once. Several photographs of the same panel are merged before pricing, taking the maximum rather than the sum, so taking more photographs cannot inflate the bill.
  • The component is supplied, not guessed. No class in the dataset names a panel, so the owner says which panel each angle shows, and every default is editable.
  • The split is leak-free. In the dataset export's own split, {{ ev.SPLIT_LEAK_BEFORE_COUNT }} of {{ ev.SPLIT_LEAK_BEFORE_TOTAL }} test images ({{ ev.SPLIT_LEAK_BEFORE_PERCENT|floatformat:1 }}%) were augmented copies of training photographs. Re-splitting by photograph brought that to {{ ev.SPLIT_LEAK_AFTER_COUNT }}, so the accuracy above is measured on images the model has genuinely not seen.
  • Limits are stated per class. The page says which classes have an unreliable outline and how much of the data they are, instead of reporting one flattering average.

Where the others may be stronger. Systems trained on real claims can learn real repair prices, whereas this project uses a published price list of approximate ranges, not workshop quotations or an insurer's schedule. The trade is accuracy of price for traceability of every figure.

How an assessment is produced

Four stages
  1. Photograph the damage One slot per camera angle, plus a close-up. More angles give the estimate more to work from, and each frame is measured on its own.
  2. Segment each damaged region {{ ev.MODEL_NAME }} returns a polygon per detected region and a class, at about {{ ev.INFERENCE_MS|floatformat:1 }} ms per image.
  3. Grade severity from measured area The polygon's area as a fraction of its own frame, compared against documented per-class thresholds. The model does not predict severity; arithmetic assigns it, which is why the results page shows the measurement against the thresholds that banded it.
  4. Price it, itemised Each graded region maps to a repair action and a price range, summed with {{ gst_percent|floatformat:0 }}% GST into one docket that is stored with the figures it produced.
